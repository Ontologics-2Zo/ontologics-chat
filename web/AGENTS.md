# 화면 작업 경계

사용자는 현재 구현을 보존하고, MK-S2와 가깝게 구현한 별도 탭에만 이후 화면 수정을 적용하기로 결정했다.

- 보존본: 이 디렉터리 직속 `index.html`, `app.js`, `styles.css`, `dashboard.js`, `dashboard.css`, `graph.js`, `graph.css`. 기준 커밋 `b3ee599`. 변경하려면 현재 보존 요청을 갱신하는 사용자 지시가 있어야 한다.
- 수정 대상: `mks2/`의 화면 파일. 보존본을 참조하는 symlink/import로 바꾸거나 공통 UI 모듈에 추출해 보존본 동작까지 바꾸지 않는다.
- 탭과 수동 확인 목록: `shell.html`, `shell.css`, `shell.js`. 탭 전환 시 iframe 문서를 유지하여 현재 화면의 선택·초안·대화 상태를 보존한다. 수동 체크가 서비스 인수 상태를 변경해서는 안 된다.
- `/current/`와 `/mks2/`는 분리된 화면 URL이며 `/`는 탭을 제공한다. 원본 HTML/fixture·개인 평가·키·DB는 이 디렉터리에 넣지 않는다.
- `현재 구현`은 명시적 참조 모드의 `/api/preview`를 사용한다. MK-S2는 `/api/mks2/` 서버 세션·원장·투영·질의 API만 사용하며 참조 fixture로 대체하지 않는다. 결정적 업무 조회를 실제 모델·Agent 완료로 보고하지 않는다. 전체 서비스 연결은 공식 Task와 버전·권한 계약을 따른다.
- 최종 온톨로지 전체를 보존한다. 화면의 부분 그래프·필터·축약은 표시 범위만 바꾸며 T-Box/SHACL·관계 방향·식별자·근거를 삭제하거나 시연에 맞춰 바꾸지 않는다. 시나리오 동작과 온톨로지 전체 보존/검증을 별도 확인한다.

## 디지털 트윈 · DEC-H39

사용자가 제공한 디지털 트윈 구현의 화면을 유지한 채 MK-S2 내부의 세 번째 `#twin` 탭에 기존 서비스 조회 데이터를 연결한다. `twin.css`·시설 배치·카메라·형상·패널 구성을 기준으로 보존하고, 현재 서버 DTO·정확 수량·UNKNOWN·근거 ID를 표시하는 연결만 보완한다. 제공 묶음의 이전 `app.js`/서버 파일로 최신 코드를 덮어쓰지 않는다. 기존 두 화면과 보존본을 유지하고 같은 session/snapshot/ontology/query/events API·권한·버전 검사를 사용한다. 시설 모형과 움직이는 점은 표현이며 실제 설비/가동/물류 사건이 아니다. 원본 폴더는 읽기 전용이며 새 업무 사건·DB 초기화·모델 자동 호출을 추가하지 않는다.

## BOM 시작 진입 · DEC-H40

별도 INITIAL 환경의 BOM 미등록 답변에서 `BOM 원본 등록`은 기존 원본 접수 drawer를 연다. `BLOCKED_BOM`·BOM ID 없음이라는 서버 상태와 정확한 현재 조회 버전으로 판단하며 문구만 보고 등록을 권하지 않는다. 화면·등록8단계·승인 분리와 원형 스타일을 유지한다. 버튼 자체로 등록·승인·반영을 실행하거나 과거5품목 판단을 복사하지 않는다. 기존 환경의 문서/원장을 UI에서 초기화하는 기능은 추가하지 않는다.

## 원형 답변 표현 · DEC-H41

공유 HTML의 조회 과정→문단 답변→근거 노드 칩→버전 footer 순서를 기준으로 한다. 상세 카드·관계·시점·snapshot은 펼쳐볼 수 있게 보존하고 중요한 출처·가정·UNKNOWN을 기본 답변에서 숨기지 않는다. 문자 단위 출력은 서버 확정 본문을 표시하는 효과이며 provider 토큰 수신이나 업무 도구 실행이 아니다. 실제 모델 호출 수를 그대로 표시한다. 모든 서버 문자열은 안전한 텍스트로 처리하고 reduced-motion·전체 보기·표시 취소/수명주기·과거 답변 보존을 검증한다. 그래프·BOM 동선과 보존7파일은 그대로 유지한다.

## 연결 그래프 복원 · DEC-H43

사용자는 업무별 층/격자 대신 이전처럼 연결된 흐름과 근거 재생 단계별 확대를 요청했다. MK-S2 그래프는 실제 간선을 반영하는 고정 배치이며 BOM 원본/행/적용/문서 이력은 하나의 연결 군집으로 표시한다. 질문마다 노드 좌표를 재배치하지 않고 카메라만 이동한다. 많은 BOM 행 근거는 한 번에 강조하며 노드/관계 ID·방향·상세는 모두 유지한다. 종류 선택은 삭제/숨김이 아닌 강조이며 기본/검색/선택/전체보기·새 재생/취소/해제·reduced-motion을 보존한다. 디지털 트윈 시설과 CSS, 직속 보호7파일은 이 변경 대상이 아니다.

## 근거 접기와 순차 표시 · DEC-H44

채팅은 정확한 조회snapshot의 핵심근거6개를 먼저 표시하고 나머지는 전체개수와함께 접는다. 전체 ID/클릭/과거버전 검사는 보존한다. 이미확정된 조회단계와 본문을 순차표시하며 실제서버실행/LLM추론진행으로 꾸미지않는다. 그래프는 핵심 관계를 천천히 확대하고 BOM의 실제관계들을 한 번에 그리는 표현만추가한다. 바탕노드/관계/고정좌표와 reduced-motion/취소정리를 유지한다.

## 답변 완료 후 보조 정보 · DEC-H45

본문은 하나의 DOM으로 순차 표시하고, 완료 후 출처·근거·버전·‘그래프에서 보기’·상세를 함께 공개한다. 읽기 전용 서버 선행 조건에 따라 미등록 BOM 접수와 기존 BOM 적용 검토를 구분한다. 검토 진입은 같은 snapshot 및 문서 ID/version/hash/구성을 확인하고 기존 드로어를 연다. 원장 반영본은 확인용이며 초안 작성·검토·독립 승인·반영을 자동 실행하거나 이전 품목 판단을 복사하지 않는다.

## 공유 화면 적용 · DEC-H47

`온톨로지 · 질의` 탭은 공유 MK-S2 관계 그래프(`lanegraph.js`, `.lg-root` 범위 CSS)이며 서버 snapshot의 entities/relationships만 그린다. 묶음·파생 클래스/속성 노드는 표시 보조이고 원장 관계가 아니다. 기존 연결 그래프는 `#network`(`프로젝트 그래프`)에 그대로 둔다. 실시간 갱신은 같은 버전의 그래프 투영이 준비된 서버 snapshot만 사용하고, 해당 품목을 다룬 대화에만 상태 줄을 붙이며, 작성·답변 중에는 자동 갱신을 미룬다. 추천 질문 선택은 입력만 채우고 모델을 호출하지 않는다.

## BOM 시트 · DEC-H48

`bom.js`는 공유 시트의 블록 구성(파일 끌어놓기·SHA-256 식별·추출 통계/필터·개정 대비 차이·흐름 칩·반영 판정)을 따른다. 파일 선택은 해시 대조만 하며 일치한 서버 보관 원본만 Runner로 추출한다. 보완 요청·반려는 서버 명령이고 원장에 반영하지 않는다. `그래프에서 보기`는 같은 버전 투영이 준비된 뒤에만 연다.

## 원형 답변 카드 · DEC-H52

납기 답변 카드의 표·견적 카드·판정 목록은 서버 `answer_blocks`의 텍스트만 그린다. 가정 카드는 접힌 상태로 `원장 근거 아님`을 표시한다. 견적 선택은 기존 구매 요청 초안 양식만 열고 저장·승인·반영을 대신하지 않는다. 예약 반영 후 이전 답변은 바꾸지 않고 버전 표시만 붙인다.
