# MK-S2 개발 인수·AI 신뢰성·정량 평가 게이트

작성일: 2026-11-08 · 상태: **인계 기준 작성, 서비스 시험 미실행**

> 후속 부분 실측(2026-11-10): [정량·정성 기준선](SERVICE-EVALUATION-20261110.md)에 조회24사례/120회, 실제 기능 선택14회, 복구2유형/6회와 정성 AI 리뷰8사례를 기록했다. 아래 최초 게이트 상태는 역사적 기준이며 후속 전체 통과를 뜻하지 않는다. 독립 사람 gold·전체 CQ/비교/규모/업무 효과는 미완료다.

[자료 인덱스](SOURCE_INDEX.md)의 SRC-V17-03 개발 설계 §12.3의 G1~G5, 요구사항 AT01~08·X01~12·T12-01~15·T13-01~20·SCALE-01~08·LOAD-01~06을 보존한다. 아래 `HG-xx`는 개발 단계별 증거를 정리하는 인계 키이며 공식 수용 기준을 대체하지 않는다. 기존 offline 데이터 검증·정해진 후보 응답 검사는 서비스 완료나 실제 AI 품질 증거가 아니다.

## 4. 대표 CQ와 데이터 격리

전체 기존 CQ20개와 C/D 추가 후보의 정상·오답·근거 부족·권한·버전 사례를 보존한다. 기존 CQ01~10, B-CQ01~06, 시연 DEMO-CQ01~04의 namespace를 구분하고, 질문 A/B는 의미가 같은 기존 CQ의 확장으로 연결한다. 독립 필요성이 검토되지 않은 새 CQ ID를 확정하지 않는다.

| 고정 검증 의도 | 기대 결과·보류 조건 |
|---|---|
| 초기 회차 약속100·도착32 | 남은 고객 도착 약속68. 현재 도착·출하·창고·양품 미입고를 중복 합산하지 않음 |
| 같은 초기 기준의 추가 양품 목표 | 40. ‘신규 생산68’은 오류 |
| 계획 수율94% 가정 | `ceil(40/0.94)=43`. 예상 투입이며 확정 양품 보장이 아님. 합성 실적에서 실제로 양품40이 기록된 뒤에는 ‘합성 시연에서 양품40 확보 완료’라고 말할 수 있음 |
| 기본/예측 자재 부족 | 동일 BOM·단위·예약·가용 조건에서20/23. 1개/대 근거 미확인 시 명시 가정 또는 보류 |
| 납기 가능성 | 자재·검사·능력·운송·기한 의미/근거가 있어야 조건부 계산. 미확인 입력을0으로 채우거나 납기 확률을 생성하지 않음 |
| 3대 생산→2대 출하→1대 도착 | 같은 보드/LOT/작업/회차·개별 사건과 유효시각. 1대 도착을 반영한 새 시점에서 잔여67이며 초기32도착에 미래 사건 중복 합산 금지 |
| 전체 고객 도착 | 후속 명시 도착 사건과 수량 보존으로 총100/잔여0 확인. v1.3 완료 snapshot의 선적재로 달성하지 않음 |

v1.3 초기 원장, 입력 가능한 명령, 예상 후속 사건, gold/기대 결과를 분리한다. 정상/지연/자료누락 run은 합치지 않는다. 실제 BOM 원본·사람 검수·합성 운영 사건·의도적 오류 fixture의 출처를 구분한다. 미검수 BOM을 사람이 승인한 정답으로 승격하지 않는다.

## 5. 지표와 비교 실험

정의·분모·한계는 SRC-AI의 `METRICS_AND_EXPERIMENTS.md`를 따른다. 원문은 저장소 밖 `PRIVATE_INPUT_ROOT`에서 별도 제공받는다. 다음 11개 필수 지표와 기존 M-12 실제 업무 효과를 보존한다.

| ID | 지표 | 측정 출처 |
|---|---|---|
| M-01 | Answer Correctness | 독립 gold와 구조화 필수 판정, 원답/제공답 |
| M-02 | Faithfulness | 검증 가능한 주장–허용 근거 연결 |
| M-03 / M-04 | Context Precision / Recall | 고정 k·필수 근거 집합·권한/버전·검색 결과 |
| M-05 | Ontology Mapping Precision / Recall / F1 | 사람이 검수한 매핑·관계 gold, 평가 범위 |
| M-06 | Goal Completion Rate | 사전 적격 사례와 실제 업무 후조건 |
| M-07 | Tool Execution Accuracy | 도구 호출·인수·순서·의미 결과, 누락/불필요 호출 별도 |
| M-08 | Policy Violation Rate | 위반 시도·차단·실제 허용 분리, 정책별 분모 |
| M-09 | Recovery Success Rate | 사전에 정의한 복구 가능 장애와 중복 없는 후조건 |
| M-10 | P50 / P95 Latency | machine elapsed, 실패·보류·timeout·사용자 대기 구별 |
| M-11 | Cost per Successful Task | 실패/재시도 포함 비용 ÷ 검증된 성공, judge 별도 |
| M-12 | 실제 업무 효과 | 실제 담당자의 paired 시간·오류·재처리 기록 |

정답·분모·usage가 없으면 `null`/N/A/미측정으로 표시한다. 고정 후보 검사 통과율, SHACL 적합률, LLM 답변 정확도, 전체 업무 완료율을 서로 바꾸어 보고하지 않는다.

비교 프로필은 **B0 최소 구조화 LLM → B1 Ontology/SHACL → B2 Hybrid RAG → B3 Inner Harness → B4 Context Engineering → B5 추가 Outer 제어**다. 기존 Q0~Q4 대응과 EX-CP(checkpoint), EX-ROUTE(model router), EX-PROVIDER(direct/OpenRouter), EX-LOOP, EX-CONTEXT, EX-RAG, EX-SEC, EX-ONTOLOGY를 별도 축으로 유지한다. B0~B5가 기존 실험을 대체하지 않는다.

같은 CQ·원장·corpus·정답·도구·가능한 같은 모델·예산·실행 조건을 사용한다. 모델/provider 변경은 별도 비교로 분리한다. 각 단계 차이는 해당 순서·조건에서의 관측 증분이며 기술 하나의 순수 인과효과라고 단정하지 않는다. 필요 시 최종 시스템의 한 요소만 제거하는 ablation을 추가한다.

모든 일반 비교군에 서버 신원·권한·비밀 분리·쓰기 승인·멱등성·절대 예산을 유지한다. 보호 자체의 제거 실험은 외부 효과가 없는 격리 Fake·가상 도구·canary에서만 수행한다. 실제 운영 보안을 끄는 설정은 만들지 않는다.

## 6. 재현 증거와 공개/비공개 경계

실행마다 `dataset_version, ontology_version, rule_version, model_version/provider, seed, fixture/corpus/index/hash, git_revision, environment, profile_id, run_id, task_id, case_id, request/trace/span/attempt_id, as_of, ledger/projection_version, inputs, tool_events, validator_results, raw/released_answer_ref, outcome, usage, cost_basis, timing, limitations`를 연결한다. 정답·holdout은 runtime 검색/메모리에 제공하지 않는다.

- 실제 BOM·원문·공유 목업·개인 gold·원답·원시 trace·실험 결과의 공개 권한을 자동 가정하지 않는다. 사용자가 공개 저장소 유지·원본 별도 보관을 선택했으므로, 검토된 공개용 내용만 저장소 후보로 다룬다. 원본의 Cloud 제공도 별도 절차이며 로컬 첨부가 자동 이동하지 않는다.
- 개인 평가 데이터·결과는 Git/Docker 밖의 보호된 위치에 둔다. 공통 평가 코드·비식별 합성 fixture·계약은 검토 후 저장소에 둘 수 있다. 운영 감사는 서비스의 보호된 원장에 보존한다.
- 외부 모델/embedding/judge·외부 tracing은 별도 허용 전 호출하지 않는다. Fake로 계약·실행·저장·복구를 먼저 검증한다.
- 실제 검증 명령은 해당 Task에서 만든 manifest/lock/서비스를 확인한 뒤 기록한다. 존재하지 않는 테스트 명령이나 아직 실행하지 않은 환경을 PASS라고 적지 않는다.

## 7. 결과 보고 양식

각 릴리스는 다음 열을 분리한다.

| 항목 | 상태 | 실행 환경·버전 | 증거 | 미완료/제약 |
|---|---|---|---|---|
| 인계·계약/파일 점검 | 검토 결과 기입 | 패키지 hash | 실제 점검 결과 | 서비스 시험과 구별 |
| 로컬/Fake 서비스 통합 | NOT_RUN에서 시작 | API·DB·투영·Runner·Langfuse | 실제 후조건·재시작·오류 회귀 | Fake 품질 주장 금지 |
| 실제 AI·관측 인수 | NOT_RUN에서 시작 | 모델·provider·전송/예산 범위 | CQ 정상/오답/미확인·원답/제공답 | gold/호출 허용 미결 |
| 비교 평가·규모·성능 | NOT_MEASURED에서 시작 | 프로필·표본·부하·환경 | B0~B5/EX 및 SCALE/LOAD | 임계값·표본·누락 |
| 실제 업무 효과·운영 | NOT_MEASURED / NOT_RUN | 참여자 과업·실인증·배포 환경 | 사람 측정·운영 게이트 | 완료 전 효과 주장 금지 |

미실행 후속 CQ/기능 수를 숨기지 않는다. 중요 실패는 원인·재현·수정·재검증을 남기고, 시험을 삭제하거나 기대값을 바꾸어 성공시키지 않는다. 범위 내 게이트가 충족되면 불필요한 Agent·프레임워크·평가를 계속 늘리지 않는다.
