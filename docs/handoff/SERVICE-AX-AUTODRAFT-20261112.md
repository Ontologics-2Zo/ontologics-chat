2026-11-12 · 8874 격리 시연 · 8870 원장·DB·예산·모델 전송 범위 변경 없음

## 목적

"ORD-26041 남은 68대, 도착기한 안에 가능해?"에서 시작해 고객 도착 100대까지 한 흐름으로 보인다. 질문은 추천 질문 클릭으로 하고 텍스트 입력은 없다. 사람은 승인과 확정만 한다.

## 바뀐 것

| 영역 | 내용 |
|---|---|
| 자동 초안 (화면) | 작성자 계정 화면에서 앞 단계가 원장에 반영되면 Agent가 다음 초안 하나를 작성한다. 대상은 발주, 모의 공급확인, 입하, 수입검사, 생산, 완성품 입고, 출하, 도착, 기초 보드 이행이다. 진행 현황 상단의 "Agent 자동 초안" 버튼으로 끄고 켤 수 있으며 기본은 켜짐이다. |
| 자동 초안의 경계 | 한 번에 하나만 작성한다. 승인 대기 문서가 있으면 새로 쓰지 않는다. Agent가 쓴 초안의 기준 원장이 지나면 같은 내용으로 최신 버전에 다시 저장하고, 이전 승인은 해제된다. 같은 단계와 같은 원장 버전에서는 같은 요청 키와 같은 내용을 재사용한다. 검토, 승인, 확정은 하지 않는다. 구매 요청(견적 선택), 대체 승인, 일정 가정은 사람이 누른다. 기초 보드 이행은 구매 LOT의 수입검사가 반영된 뒤에 시작한다. |
| 한 번 클릭 | 발주, 공급확인, 입하에는 입력 폼이 없다. 식별자와 LOT 코드(숫자만, 예: `LOT-0016-123456`)를 자동으로 생성한다. 일정 가정은 "시연 일정 가정 작성" 한 번으로 저장한다. 값은 검사 1영업일, 하루 20대, 출하 준비 1영업일, 운송 2일이며 `DEMO_ASSUMPTION`으로 기록한다. |
| 공급사 추천 (서버) | `recommend_quote`는 유효하고 공급한도가 확인되며 수량을 충족하는 견적 중에서 리드타임이 짧은 순, 그다음 소계가 낮은 순으로 1건을 고르고 이유를 붙인다. 견적 조회 API, 답변의 견적 카드, 예약 이후 재비교 답변에 표시한다. 자동 선택, 발주, 송신은 없다. |
| Agent 초안 | "추천 견적으로 구매 요청 초안 만들어줘"처럼 공급사를 지정하지 않으면 추천 견적으로 제안한다. 저장 전 승인 카드는 그대로다. |
| 단계별 추천 질문 | 입하 후 검사 전: "입하된 … 부품, 이제 가용 재고로 쓸 수 있어?". 구매 LOT로 보드 생산 후: "LOT-…는 어느 보드·출하·도착까지 연결됐어?". 전량 도착 후: "이번 회차 약속 100대가 모두 고객에게 도착했어?" (남은 0대 질문은 숨김). 부족이 있고 구매 요청이 없으면 "추천 견적으로 구매 요청 초안 만들어줘"를 표시한다. |
| LOT 추적 답변 | 연속된 보드 serial은 `첫 serial – 마지막 serial`로 줄여 표시한다. |

## 남은 것

- BOM 등록은 추가 개발이 필요 없다(2026-11-12 8874 `start`에서 확인). "보관된 원본 사용" 한 번으로 74행을 추출하고, 적용 행 5개는 초기 원장의 시연 매핑 가정(미검수)으로 미리 채워진다. 작성자는 "등록 초안 저장 · 승인 요청"을, 검토자는 확인 체크 후 승인·반영을 누른다. 나머지 69행은 미확인으로 남는다.
- 계정 전환은 사람이 누른다(작성자/검토자 분리를 보이기 위함).
