## 원형 분석과 적용 순서

원형의 질의 답변은 완료 단계의 초록 점 목록 → 문단 본문과 핵심 수량 강조 → 거친 노드 전체 칩 → 원장/그래프/모델 호출 footer 순서다. 별도의 큰 수치 카드나 긴 상세 카드가 기본 답변의 중심이 아니다. 원형 질의 화면은 단계별 타이머와 그래프 경로 재생 뒤 본문을 한 번에 표시하고, 에이전트 화면은 답변 블록을 간격을 두고 붙인다. **원형에 문자 단위 출력은 없으며 이번 요청의 추가 표현 기능이다.**

적용 순서는 다음과 같다.

1. 원형 DOM/CSS·질문별 표현과 실제 서비스 DTO를 대조한다.
2. 기본 답변의 조회 과정·본문·근거 칩·버전 순서를 맞추고 상세 근거를 접힌 영역에 보존한다.
3. 서버 확정 본문에 Unicode 문자 단위 표시를 연결한다.
4. 새 질문·탭 전환·새로고침·계정 전환·접근성·정확 근거·양쪽 DB 보존을 검증한다.

원형의 고정 답변, 미래 시연 결말, 예제 부족량/대체품 재고, 가상의 모델 호출1회는 복사하지 않는다. 원본 HTML/fixtures도 공개 Git에 넣지 않는다. 원문 화면을 기능별 기준으로 대조하는 방법이며 기존 BOM8단계·대시보드·그래프·디지털 트윈 배치를 이번 작업에서 다시 변경하지 않는다.

시각 대조 후 기본 답변의 intent/conclusion과 큰 카드들을 상세 영역으로 옮겼다. 기본 화면에는 조회 과정 바로 다음에 문단이 오고, 출처·부분 확인·미확인 주의는 본문 뒤 짧은 문단으로 남긴다. 원형 대응 값은 조회 과정12px·간격3px·초록 점8px/테두리1.5px, 본문13px, 노드칩/푸터11px·칩 간격3px다. 값·문장·근거 수는 실제 서버 응답에 따라 달라지므로 원형 시연 내용 전체의 픽셀 동일성을 주장하지 않는다.

## 서비스 연결 계약

| 원형 표현 | 실제 서비스 연결 |
|---|---|
| 초록 점 조회 과정 | 서버 `answer.steps`의 완료된 조회 과정. 그래프 애니메이션이나 문자 타이머를 도구 실행으로 표시하지 않음 |
| 문단과 수량 강조 | 서버의 본문·materials/inventory 표시 필드. 수량을 재계산하거나 질문에서 예제 값을 추정하지 않음 |
| 합성·실제·가정·미확인 | 기본 답변에도 간단히 표시. 전체 범위·세부 조건은 상세에 유지 |
| 노드 칩 | 같은 snapshot의 전체 근거 ID와 표시명. 중복만 제거하며 노드를 임의로 삭제하지 않음 |
| 버전·호출 수 | 서버의 원장/투영 버전과 실제 호출 수. Fake/기능 선택/원장 계산을 구분 |
| 상세 근거 | 기존 수치 카드·관계 ID/방향·원문/검토·기준 시점·snapshot을 펼쳐볼 수 있게 보존 |
| BOM 등록 | 미등록 상태와 현재 정확 버전에서 기존 원본 접수 drawer만 열기 |

문자 표시는 이미 받은 답변을 표시하는 효과이며 provider token streaming이 아니다. 애니메이션 없이도 같은 본문·수량·근거를 볼 수 있다. reduced-motion에서는 즉시 전체를 보여주고, **모두 보기**로 표시를 즉시 마칠 수 있다. 시각적 문자 갱신을 스크린리더가 매 글자 읽지 않도록 전체 답변과 표시 상태를 분리한다. 서버 문자열을 HTML로 실행하지 않으며 정확 소수 문자열과 한글/emoji를 보존한다.

`app.js`는 화면별 presentation의 수명을 관리한다. 새 질문·숨긴 화면·refresh에는 이전 확정 본문을 끝까지 표시하며 당시 버전을 보존한다. reset·계정 무효화에는 타이머를 폐기하고 늦은 DOM 갱신을 차단한다. 그래프 재생은 별도 토큰을 사용하며 답변 표시 실패가 성공한 서버 조회를 오류 문구로 덮지 않게 한다.
