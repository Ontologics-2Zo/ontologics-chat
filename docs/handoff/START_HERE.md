# MK-S2 개발 인계 안내

대상 저장소는 `Ontologics-2Zo/ontologics-chat`이다. 화면·메뉴·핵심 동선은 MK-S2를 기준으로 삼고, 공식 v1.7의 전체 아키텍처와 업무 범위를 유지한다. 현재는 FastAPI·PostgreSQL INITIAL 원장·서버 개발 신원·일반 근거 문서 승인과 동일 버전 RDF/SHACL·Neo4j 조회를 MK-S2 탭에 연결한 로컬 개발 서비스다. 실행은 [README](../../README.md), 검증 범위는 [SERVICE-INITIAL-20261108](SERVICE-INITIAL-20261108.md)을 따른다. 실제 BOM/구매/검사·Agent/모델·전체 서비스 완료본이나 이전 미커밋 서비스 복원본은 아니다. 최초 준비 및 참조 화면 기록은 당시 범위의 역사적 증거로 보존한다.

MK-S2의 외형·메뉴·근거 경로 재생 동선은 유지하되 내용 전체를 우리 온톨로지와 원장에서 제공해야 합니다. 전체 온톨로지를 시연 시나리오에 맞춰 축소하지 마세요. 현재의 INITIAL 원장·동일 버전 그래프 조회와 일반 근거 문서 승인 slice를 보존하고, 이를 전체 BOM/자재 확보/Agent 완료로 취급하지 마세요. 선택된 환경의 작업 트리·PRIVATE_INPUT_ROOT·runtime·DB 접근을 확인하고 이미 승인된 범위에서 공식 선행 Task를 따라 이어가 주세요. 대상 버전이 같은 검증은 재사용하고 비공개 원본은 Git 밖에서 읽기 전용으로 유지해 주세요. 공개 가능한 변경은 작업 브랜치와 PR로 보존하고 기존 승인 범위를 따라 주세요. 이번 초기 원장 구현 PR의 main 병합 승인은 DEC-H24를 따르며 환경 Publish·배포·공급사 송신·운영 원장 변경은 하지 마세요.

새 채팅이 같은 환경을 사용할 수도 있고 다른 환경일 수도 있다. Git 체크아웃만으로 비공개 입력·보안 설정·실행 프로세스·DB·Git 밖 검증 산출물이 복원되지는 않는다. 먼저 실제 브랜치/커밋/미커밋 변경과 환경을 확인하며 초기화하지 않는다. `PRIVATE_INPUT_ROOT`에 공식 v1.7·MK-S2·v1.3 자료가 있는지 확인하고, 같은 버전의 무결성 증거는 재사용한다. 누락된 자료만 보호 경로로 연결한다. 화면 미리보기에는 API 키가 필요 없다.

이전 환경에서는 세 사용자 지정 키의 인증 조회가 200으로 기록됐다. 이번 실행 환경에는 해당 키가 제공되지 않았고 실제 모델 호출은 0회다. 실제 모델 연결 단계에서는 보안 설정 접근·Gateway 매핑과 이전 사용 예산을 확인한다. 키 값은 채팅·MD·Git·로그로 요청하거나 복사하지 않는다. DEC-H18/19의 모델·예산·재시도·전송 제한은 유지하며 환경 전환으로 예산을 초기화하지 않는다.

## 적용 기준

- 사용자의 최신 명시적 결정 → 공식 v1.7의 기능·도메인·아키텍처 → MK-S2의 화면·동선과 참고 규약 → 인계 작업표 순서로 읽는다. 최신 결정은 화면 기준과 구현 우선순위를 조정하며 공식 업무 요구를 폐기하지 않는다.
- 공식 문서에 남아 있는 과거 v2.6 UI 배치·메뉴 고정 지시는 MK-S2 우선 결정으로 대체됐다. 공식 화면 ID의 업무 의미·수용 기준은 보존하고 화면 대응표로 재배치한다.
- 이전 GitHub 구현은 재사용 후보 조사 자료다. 코드가 있거나 과거 테스트가 통과했다는 사실만으로 새 서비스에서 완료 처리하지 않는다.
- 과거 계획 문서에 적힌 ‘이번에는 코드 변경하지 않음’, ‘구현 보류’, ‘T00~T01만 수행’은 당시의 제한이다. 후속 사용자 요청으로 1차 구현과 제한된 실제 모델 호출이 승인됐다. 최신 승인·제외 범위는 `AGENTS.md`와 결정 문서 DEC-H13/18~24을 따른다. 문서에 언급된 기능만으로 승인 범위를 넓히지는 않는다.

## 공개 저장소와 비공개 원본

2026-11-08 사용자는 공개 저장소 유지·원본 별도 보관을 결정했다. Git에는 새 작성 문서·공통 코드·승인된 공개 fixture만 넣는다. 원본은 `PRIVATE_INPUT_ROOT`로 별도 제공한다. 개인 컴퓨터의 첨부 경로는 Cloud에서 자동으로 사용할 수 없다.

최초 인계 준비에서는 원본을 복사·hash 확인했으며 원본 파일을 수정하지 않았다. 이후 사용자는 1차 서비스 구현·제한된 실제 모델 호출과 공개 가능한 코드/문서의 별도 브랜치 업로드를 승인했고, 최신 요청에서 이번 구현의 PR 생성·main 병합을 추가 승인했다. 비공개 원문·평가 정답을 외부 모델/관측에 임의 전송하지 않으며, 환경 Publish·배포·실제 공급사 송신·운영 원장 변경은 승인 범위 밖이다.
