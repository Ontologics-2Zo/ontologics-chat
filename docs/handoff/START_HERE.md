# MK-S2 개발 인계 안내

대상 저장소는 `Ontologics-2Zo/ontologics-chat`이다. 화면·메뉴·핵심 동선은 MK-S2를 기준으로 삼고, 공식 v1.7의 전체 아키텍처와 업무 범위를 유지한다. 현재 새 환경에는 `web/`의 읽기 전용 화면과 `dev/preview_server.py`가 있으며, 실행은 [README](../../README.md)를 따른다. 이 화면은 이전 미커밋 서비스 복원본이나 실제 원장·Agent 구현 완료본이 아니다. 아래의 최초 준비 범위는 역사적 기록이며 최신 사용자 지시와 실행 기록을 우선한다.

## 새 채팅에서 이어가기

**저장소와 `codex/mks2-ui-tabs` 브랜치를 선택한다.** 화면 구현 체크포인트는 `eadb279c29e8ecfb94ef122ae700031e5976a1c9`, 기존 화면 보존 기준은 `b3ee599`다. 후속 인계 문서 수정은 같은 브랜치에 이어서 보존한다. `main`은 화면 구현을 포함하지 않으며 병합하지 않았다. Git으로 받는 명령과 Mac 실행 방법은 [README](../../README.md#zip-없이-git으로-받기)에 있다.

새 채팅에 아래 요청을 붙여넣는다.

> Ontologics-2Zo/ontologics-chat의 codex/mks2-ui-tabs 브랜치에서 이어서 진행해 주세요. AGENTS.md, web/AGENTS.md, docs/handoff/START_HERE.md와 연결 문서를 먼저 읽어 주세요. 현재 구현 탭은 b3ee599 기준으로 보존하고, 이후 화면 수정은 web/mks2/에만 적용해 주세요. MK-S2의 외형·메뉴·근거 경로 재생 동선은 유지하되 내용 전체를 우리 온톨로지와 원장에서 제공해야 합니다. 전체 온톨로지를 시연 시나리오에 맞춰 축소하지 마세요. 현재 코드는 읽기 전용 화면 보존 단계이며 실제 원장·그래프·Agent 연결 완료본이 아닙니다. 선택된 환경의 작업 트리와 PRIVATE_INPUT_ROOT 접근을 확인하고, 이미 승인된 1차 범위 안에서 공식 선행 Task에 따라 이어가 주세요. 기존 검증은 대상 버전이 같으면 재사용하고 비공개 원본은 Git 밖에서 읽기 전용으로 유지해 주세요. 공개 가능한 변경은 같은 별도 브랜치에 보존하되 main 병합·환경 Publish·배포는 하지 마세요.

새 채팅이 같은 환경을 사용할 수도 있고 다른 환경일 수도 있다. Git 체크아웃만으로 비공개 입력·보안 설정·실행 프로세스·DB·Git 밖 검증 산출물이 복원되지는 않는다. 먼저 실제 브랜치/커밋/미커밋 변경과 환경을 확인하며 초기화하지 않는다. `PRIVATE_INPUT_ROOT`에 공식 v1.7·MK-S2·v1.3 자료가 있는지 확인하고, 같은 버전의 무결성 증거는 재사용한다. 누락된 자료만 보호 경로로 연결한다. 화면 미리보기에는 API 키가 필요 없다.

현재 환경에서는 세 사용자 지정 키의 인증 조회가 200으로 확인됐지만, 이는 다른 환경의 키 존재나 실제 모델 실행 성공을 보장하지 않는다. 실제 모델 연결 단계에서는 보안 설정 접근·Gateway 매핑과 이전 사용 예산을 확인한다. 키 값은 채팅·MD·Git·로그로 요청하거나 복사하지 않는다. DEC-H18/19의 모델·예산·재시도·전송 제한은 유지하며 환경 전환으로 예산을 초기화하지 않는다.

## 적용 기준

- 사용자의 최신 명시적 결정 → 공식 v1.7의 기능·도메인·아키텍처 → MK-S2의 화면·동선과 참고 규약 → 인계 작업표 순서로 읽는다. 최신 결정은 화면 기준과 구현 우선순위를 조정하며 공식 업무 요구를 폐기하지 않는다.
- 공식 문서에 남아 있는 과거 v2.6 UI 배치·메뉴 고정 지시는 MK-S2 우선 결정으로 대체됐다. 공식 화면 ID의 업무 의미·수용 기준은 보존하고 화면 대응표로 재배치한다.
- 이전 GitHub 구현은 재사용 후보 조사 자료다. 코드가 있거나 과거 테스트가 통과했다는 사실만으로 새 서비스에서 완료 처리하지 않는다.
- 과거 계획 문서에 적힌 ‘이번에는 코드 변경하지 않음’, ‘구현 보류’, ‘T00~T01만 수행’은 당시의 제한이다. 후속 사용자 요청으로 1차 구현과 제한된 실제 모델 호출이 승인됐다. 최신 승인·제외 범위는 `AGENTS.md`와 결정 문서 DEC-H13/18~23을 따른다. 문서에 언급된 기능만으로 승인 범위를 넓히지는 않는다.

## 공개 저장소와 비공개 원본

2026-11-08 사용자는 공개 저장소 유지·원본 별도 보관을 결정했다. Git에는 새 작성 문서·공통 코드·승인된 공개 fixture만 넣는다. 원본은 `PRIVATE_INPUT_ROOT`로 별도 제공한다. 개인 컴퓨터의 첨부 경로는 Cloud에서 자동으로 사용할 수 없다.

최초 인계 준비에서는 원본을 복사·hash 확인했으며 원본 파일을 수정하지 않았다. 이후 사용자는 1차 서비스 구현·제한된 실제 모델 호출과 공개 가능한 코드/문서의 별도 브랜치 업로드를 승인했다. 비공개 원문·평가 정답을 외부 모델/관측에 임의 전송하지 않으며, main 병합·환경 Publish·배포·실제 공급사 송신·운영 원장 변경은 승인 범위 밖이다.

2. T00~T02의 기준·실행 골격·신원 선행부터 확인하고 공통 기반 T00~T08 → BOM·온톨로지 T09.1~T12.1 → 자재 확보 T13.1~T14.1 순으로 준비된 작업을 이어간다. T19.1/T22.1은 각 묶음에 적용한다. Task 하나가 끝날 때마다 후속 지시를 기다리지 않는다.
3. 그래프 연결은 공식 v1.7 전체 어휘와 v1.3 확장/adapter의 T-Box·SHACL 버전을 대조하고, INITIAL/COMMANDS/EXPECTED 변환을 검증한 뒤 PostgreSQL opening balance를 만든다. 원본의 버전과 서버 원장 버전은 구분한다. 비공개 원본에 포함된 분석 스크립트를 그대로 실행하지 않는다.
4. Domain 사건/outbox → RDF/Neo4j 투영 → SHACL·수량·근거 검증 → 같은 버전의 권한 적용 Graph/query API → 새 MK-S2 탭 순서로 연결한다. 오프라인 `ontology/graph.json`·A-Box 합집합은 미래 사건·기대값을 포함한 검토 자료이며 초기 DB나 실시간 원장의 대체물이 아니다.
5. 화면의 노드·관계·수량·근거·답변을 실제 API 결과로 교체한다. 시나리오 동작, 온톨로지 전체 보존, 디자인 일치, 실제 AI 품질을 각각 검증하고 기존 작업표/미결 문서에 실제 명령·대상·결과를 기록한다.
