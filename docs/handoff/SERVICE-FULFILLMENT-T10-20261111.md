# 회차 전량 도착까지의 이행 흐름 (T10) · DEC-H58

상태: **VERIFIED (8874 격리 시연, v11→v22)** · 실제 출하·고객 도착·납기 판단과 구분

## 배경

자재 확보(구매·입하·수입검사) 이후 고객 도착까지를 화면에서 이어 갈 수 없었다. 초기 이관의 기초 보드(일련번호 없이 수량으로만 기록된 양품·창고·운송 중 보드)는 개별 보드 흐름(PRODUCTION → FG_RECEIPT → SHIPMENT → ARRIVAL)에 태울 수 없었고, 생산 실적은 수입검사 문서에만 연결할 수 있어 초기 재고 LOT으로는 생산을 기록할 수 없었다.

## 구현

- **COHORT 문서**(`service/procurement_contracts.py` `CohortContent`, `migrations/013_cohort_documents.sql`): 기초 보드 묶음을 단계(FG_RECEIPT·SHIPMENT·ARRIVAL)별 수량으로 옮긴다. 기존 문서 흐름(작성 → 다른 계정 검토·승인 → 확정)·자기승인 금지·정확 버전·멱등·감사를 그대로 쓴다. 각 단계 수량은 초기 이관이 기록한 해당 단계 잔량(`legacy_pools`)을 넘을 수 없다.
- **LOT 기준 생산**(`ProductionContent`): 수입검사 문서 또는 재고 LOT(`lot_code`) 중 하나만 근거로 받는다. LOT 가용량과 남은 생산 수량을 서버가 검사한다. `lot_code` 고유 참조 검사는 입하(RECEIPT) 문서에만 적용한다.
- **원장·그래프 투영**(`service/procurement_state.py`): COHORT 확정 시 잔량을 옮기고 회차 도착 누계와 회차 엔티티를 갱신한다. 그래프에는 `LegacyCohort` 노드와 기존 T-Box 관계(`shipmentForRound`·`shipsCohort` 또는 근거 연결)만 쓴다. T-Box는 바꾸지 않았다.
- **화면**(`web/mks2/procurement.js`): 대시보드 확보 카드 아래 `회차 이행` 카드. 다음 단계를 한 번에 누를 수 있다: 기초 보드 입고·출하·도착, LOT별 생산 실적 기록(보드 번호 자동 부여), 개별 보드의 다음 단계. 승인 대기 중에는 작성자에게 승인 버튼을 막는다. 원장 사건 목록에 "기초 보드 …" 단계가 보인다.
- **답변**(`service/query_answers.py`): 남은 약속이 0이면 "약속 N대가 모두 고객에게 도착했습니다"라고 답한다. 개별 도착일 근거가 원장에 없어 도착기한 준수 여부는 판단하지 않는다.
