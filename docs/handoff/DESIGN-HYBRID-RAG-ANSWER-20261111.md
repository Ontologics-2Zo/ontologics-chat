# 하이브리드 검색·재정렬·AI 답변 문장 설계안

상태: P0·P1·P2·P3·P4 **VERIFIED**(전송 범위 A, 8874 격리, 로컬 재정렬 R4) · P5 미진행 · 기록: [P0](SERVICE-RETRIEVAL-P0-20261111.md), [P1·P3·P4](SERVICE-RAG-COMPOSE-20261111.md)

## 목표와 경계

- 질문 → 키워드·벡터·온톨로지 동시 검색 → 점수 융합 → 그래프 확장 → 재정렬 → AI가 근거를 조합해 자연스러운 답변 문장을 쓰는 흐름을 만든다.
- **숫자는 AI가 쓰지 않는다.** 수량·버전·판정은 지금처럼 서버가 원장으로 계산하고, AI는 문장만 쓴다. 답변 안의 모든 숫자는 서버 계산값이어야 한다.
- UNKNOWN·합성·실제 원문·시연 가정의 구분을 유지한다. AI 문장이 검사를 통과하지 못하면 지금의 결정적 답변을 그대로 보여준다.
- 원장 쓰기·승인·공급사 송신은 없다. 읽기 전용 Agent 흐름 안에서만 동작한다.

## 현재 상태

| 단계 | 상태 | 위치 |
|---|---|---|
| 키워드 BM25·ID 정확 일치 (R0) | 구현 | `service/retrieval.py` |

검색은 현재 BOM 품목 후보 검토에서만 쓰이고, 대시보드·온톨로지 질의의 Agent 답변 흐름에는 연결되어 있지 않다.

## 제안 흐름

기존 LangGraph 흐름 `route → (fulfillment_read | material_analysis) → validate` 뒤에 네 단계를 붙인다.

```
route (기존 · 모델이 기능 선택)
  → 업무 조회 (기존 · 원장 수량·카드 계산)
  → retrieve (신규 · R3: BM25 + 벡터 + 온톨로지, RRF, 2단계 확장)
  → rerank (신규 · R4: 로컬 재정렬 모델, 상위 5개)
  → compose (신규 · 모델이 답변 문장 작성)
  → verify (신규 · 결정적 검사)
  → validate (기존) → 답변
```

### 1. retrieve
- 질문과 업무 조회 결과의 핵심 ID(회차·구성·품목)를 함께 검색어로 쓴다.
- 기존 `RetrievalService.search(profile="R3", limit=20)`를 그대로 사용한다. 권한·회사·snapshot·시점·문서 hash 검사는 이미 있다.
- 결과의 `corpus_version`과 snapshot을 답변 기준과 함께 고정한다.

### 2. rerank (로컬)
- 후보: 다국어 cross-encoder 재정렬 모델(예: mMiniLM 계열 약 120MB). 지금의 벡터 모델처럼 버전·SHA256을 고정하고 CPU에서만 실행한다.
- 외부 전송이 없다. 질문·후보 20쌍 재정렬은 수백 ms 수준으로 예상한다(측정 필요).
- 모델 파일 다운로드는 별도 승인 대상이다.

### 3. compose (모델)
모델에는 **답변 꾸러미**만 보낸다.

- **사실 목록**: `F1: 남은 고객 도착 약속 · 원장 조회`, `F2: IM-0016 부족 · 원장 계산 · 부족 있음` 같은 ID·이름·출처·상태. 단계 A에서는 숫자 값을 보내지 않는다.
- **근거 목록**: 재정렬 상위 5개의 `evidence_id`·종류·출처 구분(합성/실제 원문/가정)과, 단계 B에서만 짧은 발췌.
- **출력 형식(JSON schema 고정)**: 문단 배열. 각 문단은 `text`와 `cites`(사실·근거 ID). 숫자 자리는 `⟦F2⟧`처럼 사실 ID 자리표시로만 쓴다.

서버가 자리표시를 원장 계산값으로 바꿔 넣는다. 모델은 숫자를 볼 필요도 쓸 수도 없다.

### 4. verify (결정적)
다음 중 하나라도 어기면 AI 문장을 버리고 기존 결정적 답변을 보여준다.

1. 자리표시 밖에 숫자가 없다(날짜·ID는 사실 목록의 값만 허용).
2. 모든 자리표시·`cites`가 꾸러미에 있는 ID다.
3. UNKNOWN 사실을 "충분"·"가능"·"확정"으로 바꾸지 않는다(금지 표현과 상태 대조).
4. 판정 문장은 서버 판정(`납기 판단 보류` 등)과 같은 상태다.
5. 길이 상한, 재시도는 1회만.

## 화면

- 지금의 원형 카드(의미→불량률→부족 표→일정 가정→견적→판정)는 그대로 둔다.
- 맨 위에 **"AI 요약"** 카드를 하나 더한다. 문장마다 근거 칩을 달고, 누르면 해당 카드·그래프 노드로 이동한다.
- 검사에서 떨어지면 "AI 요약을 만들지 못해 원장 계산 결과만 표시합니다"를 보여준다.
- 디지털 트윈은 지금처럼 결정적 조회를 유지한다.

## 외부 전송 단계 (결정 필요)

| 단계 | 모델에 보내는 것 | 장점 | 위험 |
|---|---|---|---|
| **A (권장 시작점)** | 사실 ID·이름·출처·상태(부족 있음/없음/UNKNOWN), 근거 ID·종류. 숫자 값·BOM 원문 없음 | 지금(기능 플래그 7개)보다 조금만 늘어남 | 문장이 다소 일반적 |
| B | A + 근거 발췌(마스킹·길이 제한, 실제 BOM 원문 일부 포함 가능) | 문장이 구체적 | 비공개 원문 일부가 ZDR 경로로 전송됨 |

두 단계 모두 같은 `azure/us` ZDR 단일 경로·fallback OFF·질문당 $0.50·같은 US$10 예산을 쓴다.

## 비용과 속도 (추정)

- 단계 A: 입력 약 1,000~1,500 토큰, 출력 약 300~400 토큰 → 질문당 약 $0.006~0.008(기존 기능 선택 $0.0005 별도).
- 100질문에 약 $0.8. 지금 남은 예산으로 충분하다.
- 지연: 재정렬 수백 ms + 문장 작성 2~5초(측정 필요). 답변 카드는 먼저 보여주고 AI 요약은 뒤이어 채울 수 있다.

## 관측

- 로컬 Langfuse: `retrieve`·`rerank`·`compose`·`verify` 단계와 꾸러미·출력(마스킹), 검사 결과.
- LangSmith: 메타데이터만(단계·토큰·비용·검사 통과 여부).

## 결정이 필요한 항목

1. 외부 전송 단계: A로 시작할지(권장), B까지 허용할지.
2. 재정렬 모델 파일 다운로드 승인(외부 다운로드, 버전·hash 고정).
3. 벡터 모델을 E5로 바꿀지: P0·P5 측정 후 결정을 권장.
4. AI 요약을 표시할 화면: 대시보드만, 또는 디지털 트윈 외 전체.
