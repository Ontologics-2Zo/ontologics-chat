## 구현

- 서버: `migrations/009_inventory_reservation.sql`(예약·감사 표, `InventoryReserved` 사건 제약), `service/reservations.py`(권한·정확 버전·예약 가능 수량 검사, 예약·사건·outbox·감사를 한 transaction으로 기록, 멱등 재시도, reducer, 영향 계산), `ledger.py`(사건 반영·사건 보기), `views.py`(예약 목록·영향·후속 추천 질문), `main.py`(`GET/POST /api/mks2/inventory/reservations`, events 응답에 snapshot 버전), `identity.py`(새 개발 계정만 추가).
- 공급사: `QuoteContent.supply_limit_qty`(없으면 미확인, 0·무제한 아님). `quote_calculation`이 주문량·여유·공급한도 판정(MET/NOT_MET/UNKNOWN)을 반환하고 PR/PO에서 공급한도 초과를 거절한다. 원장에 공급사 B 마스터가 없어 비교안 B·C는 같은 SUP-C의 포장 두 가지(공급한도 25)로 기록했다.
- 질의: `change`(수량 변경 원인)·`sourcing`(확보안 비교) 의도. 새 공식 CQ ID를 만들지 않고 B-CQ01/B-CQ04/CQ09에 연결한다. 비교 근거는 비교한 견적만 인용하고 자동 선택·발주는 없다.
- 화면: `app.js`가 3초마다 원장 사건을 확인하고, 그래프 투영이 같은 버전으로 준비된 뒤에만 새 snapshot을 읽는다. 해당 품목을 다룬 대화에만 상태 줄을 붙이며, 작성 중(구매 양식·BOM 서랍·입력 포커스)이나 답변 표시 중에는 자동 갱신을 미루고 버튼을 보인다. 과거 답변은 당시 버전으로 남는다. 모델 호출은 없다.
