## 발견한 원인

1. **규격 문자열 토큰화**: `값/전압/허용차/…`처럼 `/`로 이어진 규격이 한 토큰으로 묶여, "100nF" 같은 부분 검색이 키워드로 맞지 않는다(R0 규격 그룹 0.00). 벡터가 일부 보완한다.
2. **관계 확장이 순위에 들어가지 못함**: R3는 관계로 찾은 문서를 결과가 limit보다 적을 때만 뒤에 붙인다. 키워드·벡터 결과가 이미 10개면 관계 문서가 들어오지 못해 관계 그룹이 0.33에 머물고 R3가 R1과 거의 같다.
3. **원장 개체에 한국어 이름이 없음**: 고객·계약·대체 후보 같은 개체 문서는 영어 클래스명과 ID만 있어, "고객사 계약", "검토되지 않은 대체 후보" 같은 질문이 맞지 않는다.
4. **벡터 하한(cosine 0.45)**: 한국어 서술형 질문 일부는 후보가 하나도 남지 않는다(결과 없음 2건).

## 수정 후 재측정 (같은 24사례·같은 측정기)

색인 버전 `snapshot-hybrid/3`. 적용한 수정:

1. **규격 문자열 부분 색인**: `/`로 이어진 규격을 원래 토큰과 함께 부분별로도 색인한다.
2. **원장 개체 한국어 이름**: 화면과 같은 T-Box 한국어 클래스 이름(`web/mks2/lanegraph.js` TYPE_KO), 주요 필드 이름, 검토 상태 이름을 검색 문구로 덧붙인다. 사실 값이 아니라 검색 단서이며 `original`·근거 hash는 바뀌지 않는다.
3. **관계 점수 합산은 되돌림**: 관계로 찾은 문서를 점수 합산(RRF)에 넣는 변경을 시험했다. 같은 품목을 공유하는 견적처럼 점수가 거의 같은 형제 문서의 순서를 흔들어, 가중치 1·0.5·0.25·0.1과 1단계 제한 모두 MRR이 R1보다 낮았다(예: 가중치 1에서 Recall@5 0.66→0.62). 관계 문서는 원래대로 빈 자리만 채우고, 순위는 P2 재정렬에서 판단한다.
