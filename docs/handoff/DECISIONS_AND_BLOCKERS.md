## 2. 개발자가 공식 기준 안에서 구체화할 사항

이 항목은 사용자에게 기술 선택을 모두 되묻는 이유가 아니다. 기존 설계와 실제 환경을 확인하고 ADR에 문제·대안·선택 이유·근거·검증을 남긴다. 요구를 바꾸는 선택만 사용자 결정으로 올린다.

표의 미결은 요구사항 삭제 사유가 아니다. 필요한 입력 없이 해당 결과를 확정하지 않고, 독립 작업을 계속한다. 기존 사용자 합의와 `user_adopted`인 가정을 반복 승인 대상으로 만들지 않는다.

## 4. 확인된 구현 공백과 상태 보고

- v1.3은 오프라인 데이터/관계 검증 자료이며 서버 DB seed와 승인 실행 기록이 아니다. INITIAL/COMMANDS/EXPECTED 변환기는 아직 없다.
- SDK·LangGraph·영속 checkpoint·Langfuse·Sandbox·RAG·원장 투영은 공식 요구다. 문서에 있다는 이유로 해당 코드가 작동한다고 표시하지 않는다.
- 첫 Task는 기준자료·환경·추적표를 확인하는 T00과 backend/DB 기반 T01이다. BOM 실제 파일 처리는 공식 T08 Sandbox 선행을 만족한 뒤 T09에서 수행한다.
- T00~T01 완료가 1차 서비스 완료를 의미하지 않으며, 1차 자재 확보 완료도 전체68대 고객 도착·전체 v1.7 인수를 뜻하지 않는다.
- 모든 Task 상태는 실제 코드·테스트·실행 증거가 있을 때만 갱신한다. 현재 자료 준비의 완료와 서비스의 NOT_STARTED/NOT_RUN을 별도로 보고한다.

자세한 데이터 조건은 [데이터 이행 계약](DATA_IMPORT_CONTRACT.md), 작업 의존성은 [구현 작업표](IMPLEMENTATION_TASKS.md), 정상·실패 판정은 [인수 게이트](ACCEPTANCE_GATES.md)를 따른다.
