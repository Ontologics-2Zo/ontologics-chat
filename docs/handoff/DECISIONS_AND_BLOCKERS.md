## 4. 확인된 구현 공백과 상태 보고

## DEC-H29 · 남은 Agent 기반 작업과 새 예산 범위

사용자가 MD 작업의 잔여 구현을 이어서 진행하도록 승인했고, 프로젝트 `.env`에 세 API 키를 직접 제공했다. 키 값은 Git·문서·로그로 복사하지 않는다. 이후 “지금 10달러로 잡고 시작”하도록 명시했으므로 **이번 작업의 새 예산 범위 `mks2-agent-20261108`에 US$10**을 배정한다. 과거 사용량을 0으로 정정하는 것이 아니며 과거 기록·기존 예산 행은 보존한다. 질문 전체 US$0.50, 하위 호출 포함 재시도 최대1, 자동 모델/공급사 fallback OFF는 유지한다.

T04~T07의 제한된 조회 Agent 기반부터 이어간다. 모델에는 서버에서 생성한 허용 기능 플래그만 보내고 질문 원문·원장·실제 BOM·평가 정답·비밀은 보내지 않는다. 실제 비용/토큰 미확인은 추정값으로 채우지 않고 미확정 예약을 유지한다. 실제 제조·납기 판단, 구매·공급사 송신, 운영 원장 변경, 환경 Publish·배포를 승인한 것이 아니다. 새 코드의 main 자동 병합 승인은 포함하지 않는다. 실행과 잔여 범위는 [Agent 실행 기록](SERVICE-AGENT-20261108.md)을 따른다.

후속 사용자 결정: “다음에 충전하고 이후 사용”하도록 실제 모델 검증을 보류했다. 앱은 Fake로 재시작했고 추가 공급자 요청은 수행하지 않는다. 실패한 요청1회의 사용량/비용은 미확정으로 보존하며 새 $10 한도와 계정 충전을 혼동하지 않는다. 충전 후 사용자의 재개 요청이 있을 때 실제 연결을 다시 검증한다.

## DEC-H30 · 충전 후 실제 연결 재확인

2026-11-09 사용자가 충전 완료와 재연결 점검을 요청했다. DEC-H29의 실제 모델 보류를 이번 연결 검증에 대해 해제하며 기존 예산·실패 이력·미확정 예약을 이어 쓴다. 같은 OpenRouter 승인 모델과 기존 전송 범위·예산 한도를 적용한다. OpenRouter의 ZDR 정책에 맞춰 Azure 단일 경로를 고정하는 것은 연결 구현 수정이며 자동 공급사/model fallback을 켜는 것이 아니다. 새 main 병합·배포·원문 전송·업무 쓰기 범위를 추가하지 않는다. 실제 결과는 [재연결 기록](SERVICE-MODEL-20261109.md)을 따른다.

## DEC-H31 · MD 잔여 1차 구현과 원형 등록 동선 유지

2026-11-09 사용자는 MD 기준 잔여1차 구현을 이어가고 기존파일/DB와 승인된US$10범위를 보존하도록 요청했다. 자재 충족 표의 가정과 사내규칙 정립을 논의했으므로 현재 결정적 산식을 명시하되 새 사내규정 승인으로 처리하지 않는다. 미검수 입력·합성 재고·계획수율은 실제 확정값으로 승격하지 않는다.

후속 정정 “부품 등록도 기존 MK-S 방식”을 우선한다. 기존8단계의 품목연결에 후보 조회를 넣고, 별도 Product 메뉴/화면이나 Agent 선택 메뉴로 등록 동선을 바꾸지 않는다. 구매/입하/IQC도 원형의 본문 공급흐름 카드에서 연결한다. 독립검토·정확버전 승인·명시반영 등 서버 계약을 위한 상태만 보완한다.

내부 업무 서비스 구현과 격리 복제본의 검증은 진행하되 기존 Mac 업무 원장을 시연 사건으로 변경하지 않는다. 실제 공급사송신·운영연계·새main자동병합·배포는 추가 승인하지 않았다. 모델 원문 전송 범위·단일 공급경로·질문당예산·미확정예약은 DEC-H29/30을 그대로 따른다. 구현과 검증 및 미완료 범위는 [자재 확보 연결 기록](SERVICE-MATERIAL-FLOW-20261109.md)에 남긴다.
